# Дополнительное усиление безопасности FORTIS

8 октября 2026 года.

## Исправлено

- Смена пароля, роли и сброс MFA меняют nonce учётной записи. Старые cookie/Bearer-сессии и незавершённые запросы 2FA больше не принимаются. В режиме персональных ссылок nonce также меняет ссылку входа.
- Журнал не читает произвольный `X-Real-IP`. Один корректный IP принимается middleware только от явно доверенного транспортного peer из `TRUSTED_PROXY_IPS`; по умолчанию список пуст. Цепочки, повторные и некорректные заголовки игнорируются. Nginx должен перезаписывать заголовок, как показано в README.
- Внешний HTTP GeoIP удалён. Публичные адреса клиентов больше не отправляются онлайн-провайдеру; IPv4/IPv6 классифицируются локально. География публичных адресов без локальной GeoIP-базы отсутствует.

## Временно отключено

- Ресурсные разрешения не преобразуются в доступ ко всему IP. Новые заявки с ресурсами и выдача старых таких заявок блокируются. Для прежних ресурсных разрешений генерируется drop до conntrack established в input/forward, если адрес не разрешён независимо отдельным сетевым доступом. Каталог ресурсов сохраняется. Сетевое разрешение по определению открывает подсеть целиком.
- API агента возвращает 410 даже при отключённом флаге стандартного WireGuard. Агент нужно перевести на mTLS или подписанный challenge; предъявление публичного сертификата не является доказательством владения ключом.

Эти ограничения предотвращают использование небезопасных функций, но не заменяют реализацию ACL по протоколу/порту или нового протокола агента.

## Проверки и оставшийся риск

48 тестов прошли: смена пароля, MFA reset, отзыв сессии/challenge, доверие к proxy, отсутствие GeoIP-запросов, блокировка агента и ресурсных выдач, порядок firewall drop до established, прежние проверки мастера и TLS. npm audit: 0 известных уязвимостей.

Тесты firewall проверяют генерацию правил; применение nftables и реальные соединения нужно проверить на Linux. Отдельный непривилегированный backend и ограниченный системный сетевой помощник пока не реализованы. Стандартная Linux-служба продолжает требовать root; этот архитектурный риск остаётся.
