# Исправления безопасности FORTIS

Дата: 8 октября 2026 года. Проверка относится к коду и версиям зависимостей на эту дату.

## Сессии, proxy, раскрытие адресов

Смена пароля, роли и сброс MFA меняют nonce учётной записи: прежние сессии и незавершённые MFA challenge перестают действовать. Logout отзывает конкретную сессию. Cookie/CSRF/проверки ролей выполняются на backend.

IP берётся из TCP-соединения. Единственный `X-Real-IP` и `X-Forwarded-Proto: https` принимаются только от transport peer в `TRUSTED_PROXY_IPS`. Произвольные `X-Forwarded-For` и прямой `X-Real-IP` не определяют адрес для аудита. Reverse proxy должен перезаписывать заголовки. Все внешние GeoIP HTTP-запросы удалены.

## Ресурсы

Ресурс хранит IPv4, обязательный TCP/UDP и порт 1…65535. Ресурсная политика не превращается в разрешение всего IP. Firewall разрешает соответствующий сервис и ставит запрет остальных сервисов этого адреса перед `ct state established,related` и общими входящими разрешениями. Проверяются также ответы сервиса и отзыв последнего разрешения. Независимое сетевое разрешение остаётся более широким по явному назначению администратора.

Для ресурса добавляется маршрут /32 в клиентскую конфигурацию; маршрут сам по себе не заменяет firewall ACL. Старые записи мигрируют с protocol=NULL и не получают автоматического разрешения. Создайте явно настроенный ресурс и переоформите выдачу. Изменять адрес/порт/протокол используемого ресурса нельзя без переноса связанных доступов.

## Агент

Стандартный WireGuard включён по умолчанию. Опциональный агент v2 требует HTTPS и доказательства владения ключом сертификата: RSA-PSS/SHA-256 над всем запросом, одноразовый challenge на 120 секунд, привязка к зарегистрированному неотозванному сертификату и устройству. Challenge атомарно погашается в БД до изменения VPN; replay отклоняется. Heartbeat проверяет принадлежность сессии тому же устройству, состояние пользователя/устройства и срок доступа.

Регистрационный токен одноразовый, действует 24 часа; атомарное погашение предотвращает повторную регистрацию. Peer остаётся закрыт до успешного signed verify. Первое создание CA сериализовано файловой блокировкой; запись файлов атомарна, частичная/несогласованная CA требует восстановления из резервной копии, не заменяется автоматически. [Протокол и клиент](agent-protocol.md).

MAC/идентификатор системы не являются аппаратной аттестацией; кража закрытых клиентских ключей требует отзыва устройства. Старые неподписанные клиенты не поддерживаются.

## Привилегии

Linux backend от root не запускается. Служба `fortis` работает без capabilities от отдельной учётной записи; только данные приложения доступны для записи. Исходники, venv и сетевые серверные ключи принадлежат root. Ограниченная служба `fortis-network` не имеет HTTP API и принимает JSON через Unix-сокет; UID клиента и UID сервера проверяются через SO_PEERCRED. Не принимает shell, pickle, произвольные исполняемые файлы или пути.

Служба управляет зарегистрированными WireGuard-интерфейсами, проверяет аргументы/IPv4/ключи, применяет проверенные собственные nft-таблицы атомарной транзакцией после `nft -c`. Не исполняет wg-quick/PostUp, не подхватывает чужие конфигурации и маскирует серверный private key в dump. Закрытые ключи сервера и резервные копии Netplan доступны только root. При перезапуске помощник восстанавливает незавершённую сетевую транзакцию; ошибка восстановления требует консоли.

Это уменьшает последствия компрометации HTTP backend, но не превращает сетевой помощник в защиту от всех сетевых злоупотреблений: управление сетью остаётся его назначением. Установку выполняет root, backend — пользователь fortis. Скрипт и службы: [deploy](../deploy/).

## Проверено

- 58 backend-тестов: мастер, сессии, MFA, CSRF, proxy, TLS, AD secret storage, схемы ресурсов, генерация ACL, подпись/tamper/replay, одноразовая регистрация, настоящий verify/heartbeat, принадлежность сессии и истечение доступа, одновременное создание CA.
- Изолированный Linux/Docker: настоящий WireGuard-туннель; TCP/UDP echo разрешён только на заданном сервисе; соседний порт и другой протокол блокируются; установленный TCP-поток блокируется после отзыва TCP-разрешения. Все backend-тесты также выполнены непривилегированным UID.
- Linux: backend не читает серверный private key; dump маскирует его; произвольная команда отклоняется; посторонний UID даже с группой сокета не получает ответ. Диагностика каналов и ограниченный ICMP работают через помощник без привилегий backend.
- UI: сборка и TypeScript; отдельная браузерная проверка создания/редактирования ресурса и TCP/UDP.
- npm audit: 0 известных уязвимостей. Ранее проверенные Python-зависимости не менялись.

Применение Netplan к физической карте, работа unit-файлов под systemd на Ubuntu и реальное подключение к AD не проверяются контейнерной имитацией. Перед эксплуатацией ручной настройки сети проверьте её на целевом сервере с доступной консолью. История сканирования не является гарантией отсутствия будущих уязвимостей.
